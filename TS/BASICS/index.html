TypeScript Fundamentals

Built-in Types

The major benefit of typeScript is being able to constraint the data type of a variable to ensure it will function properly based on the type of data it will hold. Any goes against this idea.

Base JS has:

  • number
  • string
  • boolean
  • null
  • undefined
  • object

TypeScript introduces:

  • any: able to hold any type of data
  • unknown
  • never
  • enum
  • tuple

Arrays

Two important points I noticed on this subsection:

  • If you annotate the data type of an array typeScript will suggest methods related to the data type of the elements in methods like forEach()
  • TypeScript ensures an element must exist before allowing you to display it. In my case Im checking if the output location exist before appending the values below.

Tuples

Similarly to arrays, Tuples also store multiple values, but you must specify the data type of each cell.

For example: let author: [string, number] = ["Omar", 22];

Tells the program it will store a string "Omar" and a number 22 in author. Where author[0] maps to "Omar" and author[1] to 22. This allows me to display such information

One Major issue with Tuples comes from the push() method which allows the entrance of values without specifying their data types

Enums

Enums work similarly to C by defining a set of named constant values.

The main difference is that C allows you to directly access the elements of an enum. While TypeScript enforce the use of the enum name (name.property).
